How I run it

Four decisions, and what each one costs

Most of the job is choosing, and every choice here gave something up. These are the four that shape the project most.

  1. Online co-op

    Each player's machine owns their own character

    Online play is client-host. Your machine runs your character exactly as it does in splitscreen, your partner's character is a puppet on your screen, and the host owns the world: enemies, puzzles, pickups and the save.

    Why
    A platformer lives on input latency, and this way your own character never waits on the network. The state machines that already drive both heroes run untouched. Rollback was the alternative, and it needs a deterministic simulation, which this game does not have.
    Cost
    The two players can disagree for one round trip. That only matters where the characters touch each other, so those moves need the most care.
    Tested
    With two instances at a simulated 150 ms of lag, before it reaches a playtest. How it feels on a real connection is still to be proven.

  2. The pipeline

    Every change lands through a pull request

    Everyone works on their own branch and opens a pull request into a shared integration branch. Each one goes through me or one of the founders. A small change is reviewed as a diff; a bigger one is opened in Unity and played before it merges.

    Why
    A Unity merge can come back with no conflicts and still be wrong. Scenes, prefabs and materials do not merge as text, so no conflicts means the text lined up, not that the project still works.
    Cost
    Finished work waits on a reviewer. And my own code is the gap: I merge my own pull requests, so it leans on the automated tests and the playtest build, not on a second reader.
    Result
    A tagged playtest build every fortnight. Anyone who would rather not open a pull request pushes their branch and tells me, and I open it for them.

  3. Architecture

    Layers that only point one way

    The code is split into core, game, online and UI layers. Each is its own assembly, so the compiler refuses a reference that points the wrong way. Logic that needs no engine sits at the bottom, where it can be unit tested.

    Why
    Gameplay code named the online session in 1,022 places, by the count of the repo's own metrics tool, so a feature and its netcode could only ever change together.
    Cost
    It is not finished. Inside the game layer the player, the enemies and the level tools still reference each other, and that is the next cut.
    Result
    That count is now zero. Automated tests hold the feel of the moveset and the combat to recorded baselines.

  4. Performance

    Nothing is faster until it is measured

    Performance work is compared branch against branch, on the same scene at the same quality tier, with a profiling tool I made for the team.

    Why
    Split screen draws the world twice, so a change that looks free on one camera can cost double. A number settles the argument.
    Cost
    It is slower. A change is not called faster until the same scene has been captured on both branches.
    Result
    The latest pass took 15 to 18% of the draw calls out of split screen on the lowest quality tier. What I do not have yet is a frame time for the whole game on the hardware we are aiming at. That benchmark is still to run.

Selected work

Cyber Station

A neon station management game about building a transport hub that can take the pressure. 86 scripts and around 17,000 lines, on my own.

Hundreds of passengers run off one fixed 10 Hz tick, and each picks a facility by lowest estimated total delay: queue wait plus real NavMesh walk time, both in seconds.

Minimalists

A node conquest RTS pared back to its essentials: capture structures, commit forces by percentage, and win anything from a duel to a four way free for all.

The enemy AI has no extra information. It scores every source and target pair by distance and garrison, then commits through the same send call the player's slider drives. There are six of them.

May 2025 · Unity 6 · Solo · Game jam

Wanted

A top-down stealth survival game with no win state, only a clock. The police arrive car by car and never leave.

One detection meter fills four times slower under cover, and a confirmed sighting redirects only the closest 10% of officers, so the response scales with the force.

Unicellular

An idle simulation that rewards the player for pushing the entity count up, so every cell has to stay cheap to simulate.

About

Background

I've been making games in Unity and C# since 2018, and building them consistently since 2023. I graduated from Teesside in July 2026 with a First.

The part of games I enjoy most is the systems layer: state machines driving characters and enemy AI, and the profiling and optimisation that lets a scene keep its frame budget once everything is running at once.

What I have not done yet is ship a commercial game. Out of Water is how I intend to fix that.
